## Description

Positioning: the open-source team harness — lead with the shared kb and the review lane

Research (2026-10-02) asked why no open-source project combines a cross-repo team kb, a human review lane for intent, branch-tied plans and hook/CI gates. Findings: well-resourced companies build this internally and keep it closed (OpenAI 'Harness engineering': docs/ as system of record + linters; Uber's agentic SDLC context graph; Spotify Honk/Backstage-over-MCP; Stripe Minions; ~15 in-house builds in Ry Walker's survey, top driver 'inaccessible context'). The rest of the gap is open-core economics: OpenSpec (YC) is building paid 'Workspaces for teams / multi-repo planning' and closed a community multi-repo PR; Cursor team rules, Copilot org instructions/Spaces and Tessl private workspaces are all paid tiers. Spec Kit 1.0 ('SDD or any other process', 35+ agents) overlaps process-as-config, so plain SDD is a crowded pitch.

Proposal: (1) README/positioning leads with 'the open-source, self-hosted version of the internal agent harness platforms big companies build' — shared cross-repo kb + review lane + enforcement-not-prompts; (2) publish an explicit 'team features are never paywalled' commitment; (3) target team/platform leads, not solo devs; (4) treat process-as-config as the 'fits your culture' answer, not the headline.

Feeds the README rewrite (PR #58 lineage) and the public release program spec.
